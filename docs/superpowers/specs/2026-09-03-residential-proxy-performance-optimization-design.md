# 固定住宅代理性能优化设计

## 目标

在保持当前固定住宅出口 IP `204.1.x.x` 不变、所有境外流量继续使用该住宅出口的前提下，定位并尽可能改善 ChatGPT、OpenAI 和 Cloudflare 方向的高延迟与低下载吞吐，同时保留当前 VLESS + REALITY/TCP 入口作为可靠回退。

## 已确认事实

- 当前客户端入口是 VLESS + REALITY、TCP 443；`udp: true` 只表示允许转发 UDP，不会把外层传输变成 UDP。
- `file-02` 与当前线路的客户端协议、端口、规则和主要参数基本一致，但使用不同 VPS、不同住宅代理供应商和不同住宅出口。
- 当前线路通过固定住宅出口访问 Google CDN 时，500 KB 下载约为 1.12 MB/s。
- 当前线路访问 Cloudflare 测速端点时，500 KB 在 30 秒内未完成，平均约为 16 KB/s；100 KB 复测约为 39 KB/s。
- `file-02` 访问同一 Cloudflare 端点时，500 KB 下载约为 171 KB/s。
- 当前线路与 `file-02` 的上传测试均约为 136–145 KB/s，异常主要集中在当前固定住宅出口的 Cloudflare 下行方向。
- 本机到当前 VPS 的 RTT 通常约为 190–200 ms，观测到间歇性丢包和 TCP 建连尖峰；路由延迟在跨境出口段明显上升。
- 当前有约 100 条以上活动连接使用住宅出口。供应商的并发数、带宽限制和网关策略尚未确认。
- Chrome 的 `ChatGPT Degrade Checker 降级检查` 扩展会从 `document_start` 接管 `window.fetch`，增加请求克隆、解析和失败重试开销，但无扩展浏览器仍需要约 5 秒加载，因此它是次要放大因素，不是唯一根因。

## 约束

- 必须保留当前固定住宅出口 IP，优化过程中不得让业务流量意外变为 VPS 机房出口。
- 所有境外流量仍需使用当前住宅出口，不能把非 OpenAI 流量切换到 `file-02`。
- 不覆盖现有 VLESS + REALITY/TCP 配置；所有修改先备份并提供明确回滚步骤。
- 不停止或抢占 VPS 上现有 Nginx、Xray、3x-ui 和其他生产服务。
- 住宅代理用户名、密码、VLESS UUID、REALITY 私钥及完整出口 IP 不写入仓库或聊天记录。

## 方案选择

### 方案 A：保留出口 IP，优先优化供应商路径（推荐）

先在 VPS 上分别测试直连与经过住宅 SOCKS5 访问 Cloudflare、Google 和 ChatGPT 的表现。若只有住宅 SOCKS5 到 Cloudflare 慢，则向供应商确认：同一固定出口 IP 是否支持替换接入域名、网关、机房或端口，以及套餐的并发数、单连接带宽和总带宽限制。

优点是直接处理已观测到的主要瓶颈，并满足固定 IP 约束。缺点是最终改善取决于供应商是否能调整其内部路由或接入网关。

### 方案 B：优化 Mac 到 VPS 的外层传输

在 UDP 443 不冲突且证书可用时，并行新增 Hysteria2/UDP 入口；当前 VLESS/TCP 443 保留为回退。客户端同时保留两个节点，只在验证通过后将 Hysteria2 设为默认。可选的本地整理包括只保留 TUN、关闭系统代理，以及暂停 ChatGPT 辅助扩展做浏览器差分。

优点是能降低跨境丢包对 TCP 队头阻塞的影响。缺点是无法修复住宅供应商到 Cloudflare 的下行路由或限速，因此只作为第二层优化。

### 方案 C：更换住宅供应商或住宅 IP

若供应商无法在保持出口 IP 的前提下调整网关、路由或套餐限制，更换供应商最可能达到 `file-02` 的性能，但会改变固定住宅 IP，违反当前约束。因此它只作为明确的最后手段，不纳入本轮实施范围。

## 分阶段设计

### 阶段 1：VPS 端四象限基线

在当前 VPS 上测量以下组合，每个组合至少重复五次：

1. VPS 直连 Google CDN；
2. VPS 通过住宅 SOCKS5 访问 Google CDN；
3. VPS 直连 Cloudflare；
4. VPS 通过住宅 SOCKS5 访问 Cloudflare。

同时记录 TLS、首字节、总耗时和下载速度，不输出代理密码。如果直连 Cloudflare 快而住宅 SOCKS5 慢，即可把主要问题确定为住宅供应商路径；如果两者都慢，则先处理 VPS 的出口路由。

### 阶段 2：供应商侧保留 IP 优化

向供应商提交带时间戳的测试结果，要求确认：

- 当前固定 IP 可用的所有接入域名、机房网关和端口；
- 切换接入网关后出口 IP 是否保持不变；
- TCP 并发上限、单连接带宽、总带宽和流量整形策略；
- 对 Cloudflare/OpenAI 是否存在已知路由或限速问题。

每次只切换一个接入参数，并先在 VPS 上验证出口 IP 不变，再进行性能对照。任何导致出口 IP 变化的选项立即回滚。

### 阶段 3：并行新增 Hysteria2

先只读确认 UDP 443 是否空闲、证书实际路径、Mihomo 版本和防火墙规则。满足条件后新增 Hysteria2 listener，使其仍转发到同一个住宅 SOCKS5 出站。TCP 443 与 UDP 443 可以并存，但不得假设现状；必须以实际监听结果为准。

客户端新增独立 Hysteria2 节点，不改写现有 VLESS 节点。完成配置语法检查、UDP 监听检查、出口 IP 检查和性能测试后，才允许切换默认节点。若 UDP 被运营商阻断或抖动更大，立即切回 VLESS。

### 阶段 4：客户端与浏览器减负

- 在 Hysteria2/VLESS 对照测试后再决定是否采用 TUN-only；当前数据表明系统代理与 TUN 的小请求性能接近，因此这不是主优化项。
- 暂停 `ChatGPT Degrade Checker 降级检查` 后复测页面加载和流式回复；若没有稳定改善，则恢复扩展。
- 记录住宅线路活动连接数。若供应商存在并发限制，关闭不必要的长期连接或升级套餐，但不改变境外流量必须使用住宅出口的规则。

## 验证与成功标准

每个阶段使用相同目标、数据量和测试次数，避免凭体感判断：

- 住宅出口 IP 始终保持为当前固定 IP；任何一次变化都判定失败并回滚。
- Cloudflare 500 KB 下载在 4 秒内完成，平均速度至少 125 KB/s；目标是接近 `file-02` 的约 171 KB/s。
- ChatGPT 小请求连续五次无超时，首字节 p95 不高于 2 秒。
- 无扩展浏览器的 ChatGPT 首屏加载目标不高于 3 秒。
- Google CDN 性能不能较当前基线下降超过 20%。
- VPS 上现有 TCP/UDP 监听、Nginx 虚拟主机、Xray/3x-ui 和其他生产服务不受影响。
- VPS 和 Clash 重载或重启后，住宅出口及回退节点仍可用。

## 回滚与故障处理

- 服务端和客户端配置均在修改前创建带时间戳的权限受限备份。
- VLESS/TCP 节点全程保留。Hysteria2 出现握手失败、丢包增加、出口变化或应用兼容问题时，只切回 VLESS，不删除证据。
- 供应商网关切换前记录原接入地址和端口；出口 IP 或性能不符合标准时恢复原值。
- 配置语法检查失败时不重启服务；重启后服务不 active 时立即恢复备份。
- 只保存脱敏指标，不保存明文凭据或完整密钥。

## 实施边界

本轮实施优先完成阶段 1，并根据证据决定是否进入供应商调整和 Hysteria2 部署。供应商无法提供同 IP 的替代网关时，不承诺仅靠客户端参数达到 `file-02` 的 Cloudflare 性能。
